# Delete from Policies, keep history — 2 November 2026

Admin and Policy Owner now have an explicit Delete button for disabled, inactive published policies, including those that later have draft edits. Confirmation explains that published versions and audit history are retained. After deletion, the policy disappears from policy management, search, filters, simulator selection and workspace policy counts. It is not physically purged: a retained DELETED policy record keeps immutable snapshots and all existing execution/audit references intact. Existing never-published draft deletion remains supported.

In Audit & reports → Policy history, the `policy.removed` event includes **View retained versions**, opening a named, read-only, paginated snapshot history. The original execution history remains unchanged. No actual user policy is removed by installing this feature.

Published deletion requires the loaded If-Match version and rejects missing/stale versions (428/412), enabled policies (409), or the currently assigned policy (409). The UI explains active assignment and disables Delete until another policy is activated. Backend guards prevent subsequent edit, simulation, rollback, enablement or lifecycle advancement of a deleted policy. Cross-tenant reads/writes remain denied. Activation uses an optimistic-version update before assignment to prevent stale activation from resurrecting a removed policy.

Validation: **443 backend tests passed**, including preservation of snapshots/executions/audits, deletion protections, tenant isolation and a two-session stale-activation scenario; **22 frontend tests passed**, including Delete and retained-history UI tests and actual disposable-backend integration. Ruff, ESLint, TypeScript and production build passed. A legacy protocol assertion was updated from row version 10 to 12 because its two activations now advance concurrency versions. Final full backend run passed after this correction.

SELECT-only Azure SQL checks confirmed the updated listing/pagination/search query succeeds and the existing policies table has no incompatible status check constraint.
